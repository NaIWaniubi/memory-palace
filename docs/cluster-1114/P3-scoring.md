## 维度 1 · 创新（自评 18–21 / 25）

**① 当前几分 + 证据**
诚实自评 18–21（`SCORING.md §2`，已从 20–23 主动下调）。立足点是**组合完整性**而非单点首创：`docs/COMPETITORS.md` 25 款取证里「真实空间锚定」∧「遗忘曲线调度」同时为是 = 0 款。真正的创新硬件在代码里是可验证的两件事：
- 遗忘曲线**驱动空间外观**：`core/schedule/MemoryStrength.kt` 的 `tier()`(0.33/0.66) 直连 `Theme.kt` 的 `FadedMid/FadedDeep`，卡片"长相"=记忆强度（✅ 实测 `M6-TIME-MACHINE-TEST.md`）。
- 家具语义落点：`SemanticLabelType` 24 类语义→`RoomPlaneMapper`→锚点 `anchorLabel`→卡面「📍钉在桌面上」（✅ 模拟器实测，`PLANE-ANCHOR.md §4`）。

**② 评委一眼扣分点**
- 主张"0 款做组合"的**反证检索是间接的**：PICO 官方商店 API 一直 `internal error`，退到 SideQuest 索引 34 词（`docs/evidence/2026-11-13-pico-store-recheck.md`）。评委若较真"你怎么知道 PICO 上没有"，答案的边界（`PITCH-SCRIPT.md Q4`）诚实但**弱**——只能证"没找到"，不能证"没有"。
- 记忆宫殿 loci + SM-2 都是公开古法，`SCORING.md §2` 自己列了三条扣分；**"第一次体验"的落点被压在实现层，概念层不新鲜**。

**③ ROI 最高的提分动作（可开工）**
1. **把"空间音频方位引导"从纸面变成可核查证据**（见维度4）。这是 `COMPETITORS §5.2差异点3` 唯一"0 家覆盖"的地板项，目前只验到 `play()` 调用——**它是创新叙事里最容易塌的一块，也是补齐后最能把"组合完整性"坐实的一块**。哪怕模拟器上做一个**逻辑方位罗盘可视化**(把目标锚点世界向量投到用户水平面、画出夹角与"在左/在右/在前")，就能把"没人做过的听觉路标"变成评委眼前看得见的东西。成本半天，直接抬创新地板。
2. 在 README/路演把"**家具锚定 vs 虚拟地标**"这条对 LOCI 的区隔做成**一张对比图**(左：我们的卡真钉在识别出的桌面上，右：LOCI 的虚拟宫殿地标)。当前区隔只在文字里，评委要读。

**④ "第一次体验"级 wow 点 · 现在做到了没**
- **时间机器一键让整屋记忆褪色**(✅ 已实现已实测，`M6`)：这是最强的"第一次看得见遗忘曲线"体验，`PITCH-SCRIPT §1-4` 把它定为全场高潮，判断正确。**已做到**。
- **空间会主动用声音叫你回到那张卡前**(❌ 听感未验，只到调用层 ⚠️)：这是"第一次"卖点的核心，但目前是纸面。没做到=最该补。
- 把知识钉到真实家具上(✅ 模拟器链路通，扳机❌)。

## 维度 2 · 功能设计（自评 20–23 / 25）

**① 当前几分 + 证据**
闭环六环节里五环 ✅：导入(CSV/TXT/apkg+确认页)、锚定闭环(杀进程按UUID找回)、SM-2 两档调度、遗忘可视化、复习流。代码属实：`ImportService.kt`/`CardRepository.kt`/`ReviewSession.kt` 链路完整，非 PPT。

**② 评委一眼扣分点**
- **"是否解决真实需求"缺最硬的证据——没有真实使用数据墙**。`SCORING.md §1` 自评里"每日真实使用❌11/28起""非开发者7天❌11/23起"。**11/14 评审准备期，这两条都还是空**。评委问"你自己天天用吗"，当前只能答"马上开始"。
- **"可用时长/内容丰富度"偏薄**：3 套预置牌组 50 张(`M7`)、场景只有"书房/房间层"一个空间。`功能矩阵`无第二场景(厨房/教室/通勤随身第二形态虽有随身卡窗，但内容形态单一)。
- apkg 支持不含 `anki21b/zstd`(功能矩阵自标)。Anki 重度用户的牌组导入会**静默失败**——这恰是"真实需求"主力人群。

**③ ROI 最高的提分动作**
1. **立刻起"每日使用记录"墙并公开**：从评审前推到能积累的天数，README 开一栏 log(日期/复习张数/截图)。断签一次证据链断一次(`SCORING §2` 原话)。这是把"解决真实需求"从口述变实证的唯一路径，成本=纪律不成本钱。
2. **补 zstd/anki21b 导入**或在确认页对 zstd 牌组给明确报错+"请转 anki2"提示：当前 `ApkgExtractor` 遇到会走到 `IllegalArgumentException`("没有collection.anki2/21"，`ImportService.kt:184`)，对评委演示 apkg 时一旦是 zstd 直接显示"0 条/失败"，很难看。
3. **加一个第二内容形态**(如"生活清单/考前公式墙"场景模板)把"50 张"变成"多种用法"，撑丰富度。

**④ wow**
时间机器把抽象算法变可感知——这是功能维度里唯一"亮点级"设计，✅已落地。其余是扎实的"功能成立"，不是"功能惊喜"。

## 维度 3 · 界面视觉（自评 11–13 / 15）

**① 当前几分 + 证据**
设计规范数字化是真的(`DESIGN.md` token 表 + `Theme.kt` 唯一来源 + 行高1.3统一)。深色克制路线，一致性可保下限。

**② 评委一眼扣分点（这是最伤第一印象的维度）**
- **README 头图 `demo_s1_coldstart_3win.jpg` 和 `m16-planes-aim.jpg` 展示的是"开发探针面板"**：满屏"实例号 #1(切换双态后变化=窗口被销毁重建)"、"计数+1(切换后归零=状态丢失)"、黑底 logcat 事件日志、"adb shell am broadcast…" 命令行。这正是 `DemoMode.kt:10-16` 注释里**自己批判过**的"像未完成脚手架不像产品"。**默认态其实是干净产品(`DemoMode._enabled=true`)，但对外头图用的是探针关闭态**——评委看 README 第一眼 = 开发者工具。这是本维度最大的、也是最该立刻修的丢分点。
- **房间层锚定卡重叠在原点**：`m16-planes-aim.jpg` 里 `serendipity` 卡片三张摞在一起浮在坐垫上，没有真实空间分散。`fallbackEntity` 用记录位姿直渲，模拟注入点集中→视觉成"一坨"。评委看到的是 MR 拼接 bug 观感。
- **书房面板本质是一列文字+小圆角按钮**，无图标、无分组卡片化、无进度/状态可视化、无空态插画。`DESIGN.md` 有 token 但没有视觉"作品感"。三窗截图的窗口是 PICO 默认毛玻璃，文字白字在亮背景(坐垫)上对比不足。

**③ ROI 最高的提分动作（按性价比）**
1. **换 README 头图 + demo 录屏为演示模式(净界面)**：成本≈10 分钟(应用已支持 DemoMode 默认开)，**视觉第一印象直接从"脚手架"变"产品"**，全维度最高 ROI 的一处。所有对外截图重取一遍(探针关、演示模式开)。
2. **锚定卡自动分散布局**：在 `fallbackEntity`/注入路径按记录序号给 xy 偏移或按语义分区，杜绝叠在原点。改 `RoomStage.kt:101-126` 的落点，成本中。
3. 书房面板**分组卡片化 + 图标 + 到期数做成大号数字卡**，弱化说明性长文案。成本中。

**④ wow**
褪色三档(`FadedMid/FadedDeep`)让"记忆强度"有视觉语言——这是视觉维度里唯一服务创新主张的设计，✅做到。整体仍是"规范化的极简"，不是"惊艳的画面表现"，与 `SCORING §2` 判断一致。

## 维度 4 · 交互体验（自评 12–14，未验按 10–12 / 15）

> 官方细则原文点名三条：**是否支持多窗口**(基本要求) / **是否用3D/空间交互/空间音频/MR** / **手柄/手势是否自然**。逐条对照：

**① 多窗口——✅已做到(本维度最稳的一项)**
Shared Space 双 WindowContainer(书房1280×720 + 随身卡420×560) + Full Space Stage，三窗并存截图可证(`m1-02-full-with-windows.jpg`)。`DUAL-STATE-TEST.md` 实测切双态窗口不销毁、实例号不变。**基本要求满足**，这块能拿。

**② 空间特性——3D内容/MR ✅；空间音频 ⚠️ 到纸面**
3D锚定卡+平面语义 MR 是真跑通的(`PLANE-ANCHOR.md`)。**空间音频：`SpatialCue.kt` 用 `ObjectAudioComponent`+`DistanceAttenuationMode.INVERSE_SQUARED` 把音源挂实体，代码完整，但"走到冰箱前声音在左"从未被听到**(`M12-M14-TEST §3` 只验 `play()` 调用，模拟器无空间音频输出)。细则明写"空间音频"是拉分项——**当前是"写了没响过"**。

**③ 手柄/手势——⚠️代码全做完，验证全空缺**
`AimPlacement.kt` 手柄+手势双通道(射线求交/扳机/捏合阈值0.6/幂等连发保护)写得专业，但：
- 手柄：模拟器 `ControllerTrackingProvider = DEVICE_NOT_SUPPORTED` → **扳机这一下没验过**(功能矩阵⚠️)。
- 手势：`HandTrackingProvider = SUPPORTED` 但"没有真人的手在指" → 捏合也没验。
评委看到的是"招牌交互一秒没演示出来"(`SCORING §2`)。**"做了还是标了待验？"——答案是：代码做了，交互待验。** 如实标⚠️是对的，但待验=这部分分拿不满。

**④ 评委一眼扣分点**
- 空间音频"方位/衰减"零证据(连模拟器可显示的逻辑证据都没有)。
- 手柄/手势没有任何一帧实录。
- 准星只是悬着的◎，打墙时不躺平、命中面不描边高亮(`PLANE-ANCHOR §9.4`)，"自然感"打折。

**⑤ ROI 最高的提分动作**
1. **空间音频做"逻辑方位罗盘"可视化**(同维度1动作1)：模拟器无扬声器也能把"目标锚点在用户左前方35°、距离2.1m"用面板罗盘画出来——**把不可听的方位变成可见的证据**，成本半天，交互+创新双拉，且不依赖真机。
2. **给扳机加一个非手柄映射兜底**(键盘/触控→`fire()`)：`AimPlacement.onTrigger` 已是回调注入点，`AnchorScene.kt:209` 已挂；补一个 demo 触发入口，**真机借不到也能现场演示"瞄准→确认→建锚"整条链路**，把交互从纸面变可演示。成本小-中。
3. 借到真机后优先录**一段10秒手柄放置+一段10秒空间音频转头**，作为交互维度的决定性质证(`SCORING §4` 已排期11/21–26)。

**⑥ wow**
"指向哪、贴在哪、声音从那传来"是三维联动的空间交互体验——设计目标是对的，但**当前只有"贴在哪"可演示，"声音从哪来"和"手柄指着"都待验**。

## 维度 5 · 完成度（自评 9 / 10，含"开源二开加分"）

## 维度 6 · 路演（自评 6–9 / 10）

**① 当前几分 + 证据**
`PITCH-SCRIPT.md` 是六维里最成熟的一环：5min/3min 双线逐字稿、每段"出错怎么救"、Q&A 七题、诚实声明、无真机话术降级、彩排掐表基线。这套准备度**高于大多数参赛队**。

**③ ROI 最高的提分动作**
1. 借不到真机时，**把"逻辑方位罗盘 + 键盘映射扳机 + 注入射线"串成一条模拟器可 100% 复现的"放卡→褪色→发声指向"演示链**(维度4动作1+2)，让无真机路线也有"看得见空间交互"的高潮。成本中，直接把路演下限从 6 抬向 8。

**④ wow**：全场高潮设计=时间机器+空间音频。**时间机器已可现场复现(✅)，空间音频"叫你回来"那一刻当前无真机=给不出(❌)**——它是路演最值钱的一句，也是最大的不确定。

## 30 分钟稳定性最小加固清单（准入门槛第 3 条 = 唯一硬缺口）

> 现状：全仓**没有任何 30 分钟连续运行 / 压力 / 内存泄漏实测证据**。`PITCH §511` 提到"模拟器连续运行帧率录屏"，但 docs 里查不到对应文件。这是唯一可能"不进正式评分"的红线。以下按"会不会真在 30min 内触发卡死/丢数据"排序，全部有代码位置。

1. **[高·丢数据] `AnchorStore.load()` 吞异常丢全部锚点**（详见 P2 阻断条）
   任一条记录解析抛错 → `runCatching{}.getOrElse{emptyList()}`（`AnchorStore.kt:34-56`）→ 下次 `save` 整键覆写（`:72`）→ 历史锚点含仍活的系统 UUID **永久丢失**。直接违反准入"无数据丢失"。**最小改**：逐条 map 隔离坏记录(坏的跳过、好的保留)，load 失败不覆写。

2. **[高·卡死] 导入 O(n²) → 大批量 apkg 主线程卡顿/ANR**
   `ImportService.persistImported`（`:203-218`）对每张卡单独 `repository.add()`，每次 `upsert` 触发 `dao.observeAll()` **全表 Flow 重算 + `DueQueueView` 全列表 `remember` 重算**(`StudyPanel.kt:191-193`)。导几千张 Anki 牌 → 几千次全表回读 → 数分钟级卡顿。30min 内若有人演示导入大牌组即"卡死"观感。**最小改**：一次事务批量 insert（`@Insert` List + `@Transaction`），导入期间不逐条 emit；`previewFromUri` 已在 IO 线程，但 UI 侧全量重组仍需降。

3. **[中·卡死/掉帧] `RoomStage` 用 `key(records, tick)` 整体重建 SpatialView**
   每次放卡 / 每次时间机器(+7天) 触发**整个 3D 场景销毁重建**(`RoomStage.kt:84`)，重建里又跑 `verifyRestored`→`WorldTrackingManager.loadAnchor(全量)`(`:142`)。GL 纹理 churn(自述"数秒延迟"D5)。连续操作或时间机器反复拨 → 累积卡顿。30min 反复进出房间层是压力源。**最小改**：放卡改增量挂载新实体；`tick` 重建加去抖；`verifyRestored` 仅在进入 Stage 时跑一次。

4. **[中·句柄泄漏] `SpatialCue` releaseAll 与并发 load 竞态**
   Stage 销毁 `releaseAll()` `resources.clear()`(`SpatialCue.kt:197-207`)，但一个**尚未完成的 `scope.async` 加载**可能在 clear 之后把原生 `AudioResource` 句柄写回 `resources`(`:117`)→ 该句柄再也无人 close。30min 内反复进出 Full Space(每次 attach/play 都可能触发 load)→ 原生句柄缓慢泄漏。**最小改**：`releaseAll` 里 `loading.values.forEach{cancel}` 且 `resource()` 写回前判"是否已 released/Stage 是否活跃"。

5. **[中·崩溃路径] `Geometry.normalized()` NaN 漏网**（P1 阻断）
   `len<EPS` 判零对 NaN 恒 false（`Geometry.kt:33-37`）→ 静默产 NaN 向量 → 喂进 `createAnchor`/`Reticle.move`(`RoomStage.kt` per-frame)。坏位姿/合成输入下可能渲染异常。**最小改**：入口 `if(!len.isFinite()||len<EPS) return null`。

6. **[观察项·真机才知] 启动 ANR + `openStage NotAllowed`**
   两处自判定性为"模拟器 libhoudini 转译独有"(`ANCHOR-M2-TEST §ANR`、`DUAL-STATE-TEST:47`)，但**均明写"真机复现则升级为 P0"**。这是唯一能直接判"卡死"的现存路径，且未量化。**最小改**：无论真机借到与否，在模拟器上跑一次"连续 30min、每 2min 进出 Full Space + 定时放卡/复习"脚本，记录有无 ANR/NotAllowed/内存爬升，产出 `docs/STABILITY.md`(对应机会#7)。**这条做了=准入第3条从"无证据"变"有证据"，是整个评审资格的地基。**
