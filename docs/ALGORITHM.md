# 调度算法

> 对应实现：`core/src/main/java/com/memorypalace/core/schedule/`
> 单测：`core/src/test/java/com/memorypalace/core/schedule/`（31 例，Scheduler 12 + MemoryStrength 19）

## 1. 主路径：SM-2 改进版

选 SM-2 而不是 FSRS 作为主路径，理由是**可解释 + 可单测**：评委在路演上问"你凭什么说这张卡该今天复习"，答案是能当场展示的三行规则，而不是一个黑盒模型的置信度。FSRS 保留接口位（见 §5）。

### 状态字段（全部长在卡片上，随卡片持久化）

| 字段 | 含义 | 初值 |
|---|---|---|
| `repetitions` | 连续答对次数 | 0 |
| `easiness` | 难度系数（EF），越大间隔涨得越快 | 2.5 |
| `intervalDays` | 当前复习间隔（天） | 0 |
| `dueAt` | 下次到期时间戳 | 创建时刻（立即到期） |
| `lastReviewedAt` | 上次复习时间戳 | null |

### 规则

```
EF' = EF + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))     下限 1.3
```

| 情形 | 动作 |
|---|---|
| 忘记（q=1） | `repetitions` 清零；`intervalDays` 归零；10 分钟后重新到期；EF 按公式下调（下限 1.3） |
| 记住（q=4） | `repetitions` +1；间隔：第 1 次 → 1 天，第 2 次 → 6 天，第 3 次起 → `上间隔 × EF'`（至少 1 天） |

### 为什么是"两档自评"而不是 SM-2 的五档

方案 §1.2 的核心循环是"自评记得/忘了"。空间交互里做五档打分要五次额外操作，评审现场没那么多注意力预算。两档是**为空间场景裁剪过的 SM-2**：把 q∈{0..3} 折叠成"忘了"、q∈{4,5} 折叠成"记住了"。

代价是丢了"记得但很吃力"这一档信息。补偿：EF 的下调幅度按原始公式计算（q=1 时 EF -0.54），即"忘得干脆"和"忘得勉强"在 EF 上仍有区分。代价已在 §6 列为已知折中。

### 已验证的边界行为

| 行为 | 单测 |
|---|---|
| EF 连续下降触底 1.3，不越界 | `easiness never drops below floor` |
| 连续记住时间隔单调不减 | `连续记住间隔单调不减` |
| 第 4 次记住间隔 38 天（15 × 2.5 取整） | `记住后间隔按 easiness 增长` |
| 遗忘后重新记住回到 1 天间隔 | `遗忘后重新记住回到一天间隔` |
| 重学延迟期间卡片不在到期队列 | `重学延迟把卡片排除出立即到期队列` |
| q=4 时 EF 不变（公式恰好抵消） | `easiness 记住时也会下降符合 SM2 公式` |

## 2. 时间注入：所有时间都是参数

调度器是纯函数，`now` 由调用方传入。`core/` 因此零 SDK 依赖、可纯 JVM 单测，也让 M6 时间机器成为一次普通的参数替换而不是特性分支。

```
Scheduler.review(card, Grade.REMEMBERED, now) → card'
```

应用层的时间来源是 `Clock.now()` = `System.currentTimeMillis() + offsetMillis`。时间机器只改 `offsetMillis`，调度逻辑一行不动。

## 3. 记忆强度可视化（M13 下沉到 core）

"看得见的遗忘曲线"是本项目区别于普通 Anki 的核心表达，但它最初写在 `app/ui/AnchorCard.kt` 的私有函数里 —— 无法单测。M13 把它下沉为 `core/schedule/MemoryStrength.kt`。

### 褪色度

```
fade = clamp(逾期时长 / 当前间隔, 0, 1)
```

- 未到期 → 0（清晰）
- 逾期满一个间隔 → 1（彻底褪色）

新卡的 `intervalDays` 为 0，用 1 天兜底，避免除零导致"新卡一创建就是深灰"。

### 视觉映射

| 量 | 规则 |
|---|---|
| 不透明度 | `1 - 0.7 × fade`，下限 0.3（褪色是提示，不是隐藏） |
| 文字色 | fade ≤ 0.33 白色 / ≤ 0.66 中灰 / > 0.66 深灰 |
| 标签 | 未到期"记得牢 · N 天后到期"；逾期中"正在遗忘"；逾期满间隔"快忘了" |

### 为什么下限 0.3 而不是 0

褪色到看不见就变成了"卡片消失了"，用户会以为数据丢了。0.3 的下限保证最深的褪色仍然可辨 —— 视觉强度承载的是紧迫感，不是可用性。

## 4. 到期队列

```
dueQueue(cards, now) = cards.filter { it.dueAt <= now }.sortedBy { it.dueAt }
```

按到期时间升序，最逾期的排最前 —— 逾期最久的卡最该先复习。

## 5. FSRS 演进路线

FSRS 是 SM-2 的现代替代（用记忆稳定性/难度两个连续量建模，间隔预测更准）。留位但不实现，理由：

1. FSRS 需要每个卡片的复习历史序列才能训练，当前数据模型只存聚合状态，要换就得改 schema
2. 评委问"凭什么"时，SM-2 能当场讲清，FSRS 只能讲论文
3. 时间预算：11 月剩余排期里没有"重做调度系统"的空间

演进路径已想清楚但明确排在 12/16 提交之后：新增 `review_log` 表（每卡复习历史）→ 离线训练 FSRS 参数 → 对比 A/B 保持率 → 有明显提升再替换。
