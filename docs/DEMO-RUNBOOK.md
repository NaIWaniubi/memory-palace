# 现场演示操作单（三分钟路径）

> 给没碰过本应用的操作员。全程只用手柄/射线点击，**不需要任何电脑和命令行**。
> 每步含：做什么 → 会看到什么 → 没出现怎么办。
> 实测环境：PICO Emulator 6.1（x86 转译，比真机慢）；真机待验项单独标注。

## 0. 演示前检查（30 秒）

- 头显里从应用库启动「记忆宫殿」。**冷启动到三窗出现约 12 秒（模拟器实测，真机预计更快）**。
  屏幕在这 12 秒里显示**深色底 + 应用图标的占位画面**（M12 起有，不是黑屏）—— 等，别重复点。
- 应看到：书房面板（大窗）+ 随身复习卡（小窗）+ 身后房间层。窗口冷启动自动打开（M11 修复前需 adb，已修）。
- 没看到窗口：完全退出应用（多任务里划掉）重开一次；仍没有 → 放弃现场演示，切录屏视频。

## 0b. 投屏模拟器路演：模拟器挂了怎么办（备用操作员看）

> 模拟器被内存压力杀掉是**已知会发生的事**（宿主机空闲 ~5.6GB ＜ 官方建议 12GB）。
> `--watch` 救不回来 —— 它会拒绝重启并报 "refusing to launch a second instance"。
> **口令：60 秒内没恢复就切兜底视频，不道歉不解释。**

```
tasklist | grep -iE "emulator|qemu"           # 找僵尸进程
taskkill //PID <pid> //F                       # 杀掉（Git Bash 里要用 //PID）
pico-cli emulator start --avd Pico_Emulator_6_1 --watch
```

恢复后**必须重做两件事**（模拟器重启会丢系统锚点）：

1. 重新放卡：`adb shell am broadcast -a com.memorypalace.anchor.PLACE --ef x 0.0 --ef y 1.2 --ef z -1.5 --es front "..." --es back "..."`
2. 重验位置：logcat 里应出现 `verifyRestored: ... drift=0.0m`

**注意**：模拟器端口不固定（见过 5554 与 5556），脚本别硬编码端口号。

完整版见 [M12-M14-TEST.md §6](M12-M14-TEST.md)。

## 1. 房间层看锚定卡片（0:00–0:30）

- 点书房面板「进入房间层 (Full Space)」→ 约 1–2 秒进入房间，锚定卡片悬在放置时的位置。
- 没看到卡片：点「返回共享空间」再进一次（实例号会 +1，属正常重建）。

## 2. 走到卡片前复习一张（0:30–1:00）

- 走近任意锚定卡片，点卡片上的「**复习这张**」（M11 新增，**真机待验：射线点击**）→ 随身卡窗口进入该卡的复习（正面 → 点「翻面」→ 点「记得/忘了」）。
- 每步反馈 <1.5 秒。若按钮点不动：改用书房面板「开始复习」走全局队列（等效，评委看到的是同一个复习流）。

## 3. 书房面板看队列 + 时间机器（1:00–2:00）

- 回书房面板，「今日到期队列」实时显示 N 张 / 共 M 张。
- 点「+7 天」→ 面板队列数字**立刻**跳变（<1 秒）；抬头看房间层，锚定卡片在数秒内集体褪色、标签变「快忘了」（3D 纹理刷新有数秒延迟，先讲面板再指房间，用话术盖住）。
- 点「复位」→ 全部恢复。

## 4. 导入自己的牌组（2:00–2:40）

- 点「导入牌组」→ 系统文件选择器（**真机待验：PICO 上 SAF 选择器的呈现**）→ 选 CSV/TXT/apkg → 面板弹出**导入确认页**（文件名、格式、解析条数、前 5 条预览）→ 点「确认导入」→ 队列数字立即变化（实测 52→55，1.2 秒）。
- 文件选择器打不开：用预置三套牌组（首次安装自动导入 50 张）兜底，话术「评审机已预装示例牌组」。

## 5. 收尾（2:40–3:00）

- 点「开关随身卡窗口」演示窗口随手取放（关 0.7s / 开 3.0s）。
- 一句收束：「复习过的卡片重新鲜亮，间隔被算法拉长——这就是记得住的记忆宫殿。」

# 附录 B：缺陷分级

**第一类（会卡住流程，M11 已修复）：**
- D1 冷启动后窗口不自动出现，现场没有开窗口的入口 → 已修：`autoOpenOnce()`（组合入口调用，容器未注册自动重试，实测 attempt 1 成功）。
- D2 锚定卡片没有「复习这张」入口，走到卡片前无法发起复习 → 已修：AnchorCard 按钮 + `ReviewSession.startSingle(cardId)`。
- D3 「放卡进房间」只有 adb 广播，真实用户无入口 → 已修：书房面板队列首行「钉入房间」按钮 + `AnchorScene.placeForCard`（绑定已有卡，不新建）。

**第二类（慢一点，不翻车）：**
- D4 冷启动到首窗 12s+ → **已修（M12）**：manifest 主题非透明，系统 starting window 立刻画占位画面（深底 + 应用图标），不再黑屏。**真机 arm64 原生预计更快，复测后更新此条耗时**。详见 [M12-M14-TEST.md](M12-M14-TEST.md)。
- D5 +7d 后 3D 锚卡纹理数秒才更新（面板即时）→ 演示话术可盖住；如需根治，研究纹理强制刷新。M12 已补 4.5s 自动收起的「跳转中」提示，避免现场观感成卡死。

**第三类（不好看/待验）：**
- D6 SAF 文件选择器在 PICO 真机的呈现样式未验。
- D7 模拟器无法射线点击，所有按钮交互本身列为**真机待验**（逻辑层全部由无头通道验证通过）。
- D8 空间音频与到期通知在模拟器已验（加载/播放/发出/调度/触发/撤销全部通过），**声场方位与通知弹窗呈现待真机**。

**已修复前的 adb-only 清单（现在每条都有真实 UI 对应物）：** 开窗口、复习发起、放置锚卡。广播通道保留作自动化测试用，不影响现场。

# 附录 C：M13/M14 的演示入口（2026-11-09 新增）

这两个功能在模拟器已实测通过，真机验证后可直接进路演脚本。

| 想演示 | 怎么做 | 会看到 |
|---|---|---|
| **空间音频方位引导** | 书房面板 → 到期队列首行 → 点「🔊 播报方位」 | 提示音从**那张卡的锚点位置**发出（模拟器无空间音频输出，真机才能听出方位） |
| **头显到期提醒** | 书房面板 → 「排提醒」/「立刻试响」/「撤提醒」 | 头显系统通知面板弹出「N 张卡该复习了 + 首卡内容」 |
| 提醒时刻语义 | 看面板提示 | 有未来到期的卡 → 等到那个时刻响；全部已逾期 → 5 秒后立刻响一次 |

**演示话术建议**：把「播报方位」放在「走到卡片前复习」之前 —— 先听声辨方向，再走过去翻卡。这两段连起来才是"空间主动叫你回来"的完整叙事，而不只是"又一个闪卡 App"。

**注意**：PICO OS 默认未授予精确闹钟权限（`SCHEDULE_EXACT_ALARM`），面板会显示橙色警示。**赛前在演示机上先开这个权限**，否则提醒会被系统延后。
