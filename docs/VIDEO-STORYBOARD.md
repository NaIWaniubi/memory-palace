# 参赛演示视频 · 逐镜分镜脚本（双轨）

版本：v1（2026-11-07）｜ 目标时长：150 秒 ± 10 ｜ 对应方案 §5.2
轨 A = 无真机版（默认关键路径）；轨 B = 借到真机后的替换镜头。
批次标记：**【一】= 第一批现在就能拍**（只依赖模拟器/后期），【二】= 需真机，【后】= 纯后期。

## 拍摄方式图例

- **模拟器录屏**：`adb -s emulator-5556 shell screenrecord /sdcard/x.mp4`（每次 ≤3min，注意宿主机内存纪律：录前关浏览器等大户）
- **应用内测试入口**：广播驱动（OPEN_WINDOWS / SET_OFFSET / card.PREVIEW / CONFIRM / anchor.PLACE 等），保证录屏动作可复现
- **锚定叠画**：后期把锚定卡 UI 合成到手机实拍的房间画面上（无真机时表达"空间锚定"的唯一手段）
- **真机实拍**：头显内录屏（仅轨 B）

## 第三幕半 · 空间音频方位引导（1:45–1:57，唯一"全竞品零覆盖"项）

> **为什么插这一幕**：竞品调研（`docs/COMPETITORS.md` §5.2 差异点 3）查证 25 款 XR/AR 同类产品，**空间音频用作学习内容的方位引导是零覆盖** —— 竞品的提醒形态全是视觉的（App 内卡片列表、徽章、连胜）。这是最难被评委问"这个别人也有"的一项，必须给它独立的镜头，不能只靠字幕带过。

| 15c | 6s | 视角从书房转向房间层，指向发光卡片；字幕「转头，声音在那边」 | 模拟器录屏 + 后期指向动画（模拟器无空间音频输出，**声画不同步必须标注**） | 真机实拍（声音真的在那个方向） | "声音和卡片是同一个坐标系——它在冰箱上，声音就在冰箱那边。" | 【二】 |

**诚实纪律**：轨 A 里模拟器没有空间音频输出，15c 必须做**声音效果替代**并在字幕标注「模拟器录制，无空间音频输出」—— 不能让评委以为我们伪造了声场。轨 B 是唯一能证明这一点的形态。**这也是借测真机的第二硬理由**（第一是空间交互）。

## 录屏操作备忘（实测踩过的坑）

1. 录屏前 force-stop 重启，等 ~80s Stage 前台再发 OPEN_WINDOWS；若落在房间层先发 CLOSE_STAGE 回共享空间
2. 画面水印：轨 A 全程右上角常驻「模拟器录制」标识（后期统一加，诚实声明）
3. ANR 弹窗可能出现且无法关闭（已三次确认 systemui 不响应注入事件、主线程正常）——录屏脚本把关键镜头排在弹窗出现前的窗口期，或后期裁掉弹窗区域；**真机待验项**，不再投入模拟器侧排查
4. screencap 有白帧/黑帧抖动，录屏同样可能掉帧——每个镜头录 2-3 遍取优
5. 宿主机内存仅 ~5.6GB：录屏前关闭浏览器与其他重进程，模拟器用 --watch 守护拉起
